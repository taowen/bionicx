## Generic hello profile

The reproducible hello bundle used the explicit-loader mode and the pinned
Android-compatible glibc 2.39 runtime. It connected with an ordinary libX11
client and rendered through `XPutImage`:

```text
profile=hello-x11 display=1920x1080@144 socket=filesystem
bionicx-exec: running untraced pid=6256
hello-x11: glibc=2.39 pid=6256 DISPLAY=:0 vendor=Elbrus Technologies, LLC
```

Screenshot: [hello-x11.png](hello-x11.png)

As a negative qualification test, unmodified Debian glibc 2.41 was also tried
under the normal Android app process. Diagnostic mode reported:

```text
bionicx-exec: signal=31 syscall=99 ... code=1
```

AArch64 syscall 99 is `set_robust_list`; Android's app seccomp policy delivered
`SIGSYS`. This is why the default hello builder deliberately uses the pinned
Android-compatible runtime rather than claiming arbitrary desktop glibc builds
will work unchanged.
