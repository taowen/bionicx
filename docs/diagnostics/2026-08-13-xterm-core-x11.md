# Debian xterm as a core-X11 compatibility boundary

## Scope

Debian trixie snapshot `20260811T000000Z` installs `xterm` 398-1 and its six
new dependency packages into the existing Chrome/WPS/IceWM rootfs with apt.
The resulting shared image contains 281 dpkg packages. No xterm library is
copied by hand.

The final device run uses the ordinary `io.taowen.bx` UID, diagnostics are
disabled, and `bionicx-exec` reports an untraced process. xterm starts Debian
bash 5.2 through a PTY. Android key injection executes:

```text
echo bionicx-xterm-ok
pwd
```

The terminal renders the marker and the app-private home path. Evidence is in
`evidence/bionicx-trixie-xterm.png` and
`evidence/bionicx-trixie-xterm.log`.

## Gaps exposed

This traditional Xlib client exercised core protocol paths that Qt and Chrome
usually reach through XKB, Xft or Render:

- `OpenFont`, `QueryFont`, `QueryTextExtents` and `ListFonts` needed a
  deterministic virtual fixed-width core face;
- `AllocColor`, `QueryColors` and `RecolorCursor` needed TrueColor semantics;
- `SetInputFocus` incorrectly used the revert policy to choose the focus
  window. The target and policy are now independent, and special
  `PointerRoot` focus resolves dynamically below the pointer;
- `GetKeyboardMapping` advertised two keysyms per keycode but serialized only
  one. It now returns exact lower/upper pairs;
- loader `--library-path` affected only the first glibc image. Loader-mode
  profiles now export the same `LD_LIBRARY_PATH` by default so xterm can exec
  package-installed bash without PRoot;
- Debian Fontconfig configuration and absolute `conf.d` links are relocated
  to the app-private rootfs, and bash's interpreter is relocated to the
  app-private glibc loader.

`-ut` disables utmp recording because Android does not provide a writable
system utmp database. It does not replace the PTY or shell.

## Regression

The genuine glibc/libX11 core probe now asserts fixed-font metrics and listing,
TrueColor allocation/query, cursor recoloring, independent focus target/revert
semantics, and exact two-level keyboard mapping:

```text
BXTEST PASS initial-pointer-root-focus focus=0x1 expected=0x1 revert=1
BXTEST PASS input-focus-revert-policy window=0x400001 expected=0x400001 revert=1
BXTEST PASS keyboard-mapping-levels width=2 q=0x71 Q=0x51 w=0x77 W=0x57
BXTEST PASS core-font-query width=8 ascent=11 descent=3
BXTEST PASS core-font-text-extents width=56 direction=0
BXTEST PASS core-font-list count=1
BXTEST PASS truecolor-alloc-query pixel=0x12569a rgb=1212/5656/9a9a
BXTEST PASS cursor-recolor
BXSUMMARY passed=32 failed=0 observational_input=yes
```

The complete output is retained in `evidence/x11-core-probe.log`.

## Xorg comparison

Client-visible behavior is deliberately converging on the X11 protocol and
semantics exposed by Debian's Xorg. The implementation is not converging on
Xorg internally: BionicX remains an Android in-process server with an Android
surface/input compositor and host GPU bridges. It implements the protocol
surface demanded by controlled probes and real applications, while Xorg has
far broader drivers, extensions, font backends, authorization and device
management. Passing xterm therefore demonstrates a larger compatible core
subset, not equivalence with Debian Xorg.
