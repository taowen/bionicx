# X11 PolyText8 compatibility path

## Symptom

`XDrawString` failed with `BadImplementation`, and Android logged
`Unsupported opcode 74`. Core-font clients therefore could not render even
basic diagnostic text.

## Implementation

The request dispatcher now handles PolyText8. The parser supports the X11
TextItem8 length byte, signed delta, Latin-1 payload, request padding, and
FontShift item consumption. Drawable rendering uses Android's deterministic
non-antialiased monospace face with the GC foreground color.

The strict regression reads the text rectangle back with `XGetImage` and
requires foreground pixels. This proves the handler produced drawable content,
not merely that it consumed the request.

## x300 regression

```text
BXTEST PASS poly-text8 foreground-pixels=473
BXSUMMARY passed=12 failed=0 observational_input=no
x11-probe exited with 0
```

## Deliberate boundary

This is a compatibility implementation, not yet the complete X11 core-font
model: OpenFont currently exposes only the cursor special case, FontShift IDs
are consumed but do not select a stored font, and metrics are fixed. A future
font stress client must add font resources, QueryFont/TextExtents, selectable
metrics, and a cheaper glyph path before core-font-heavy applications are
declared supported. Chromium and modern WPS normally use client-side font
rasterization, but this core request must remain correct for diagnostics and
older X11 clients.
