# WPS print to the controlled CUPS destination

Device `01408BH601027129`, seed
`ed998c095a1b9384b1f022d06101ac3fc3c61761ac751546bd84edca298e44e2`.

WPS `KCUPSSupport::isInitSuccess()` treats “no destinations” as the
misleading string “Missing Cups libraries.” `libcups.so.2` already
exports every symbol `QLibrary("cups", 2)` resolves. The remaining
contract is a live `bionicx-test` destination plus a `file:` backend.

Debian 13 `cups-daemon` ships only the `ipp` backend. The probe therefore
installs `examples/cups-probe/file-backend.c` at
`/usr/lib/cups/backend/file` (mode 0700) before `cupsd` starts.

`examples/cups-probe/cups-probe.c` then:

1. `dlopen("libcups.so.2")` (the same `QLibrary("cups", 2)` load)
2. resolves the dest/print/IPP/PPD symbols WPS binds
3. `cupsGetDests()` / `cupsGetDest("bionicx-test")`
4. `cupsPrintFile()` and checks the job payload

On this device: `BXSUMMARY wps-cups passed=25 failed=0`.

Untraced Writer opened the seed fixture. The system-check dialog no
longer lists CUPS (only the known formula-symbol warning). Ctrl+P opened
the Qt print dialog with `Name: bionicx-test`, `Status: Ready`. Return
submitted `bionicx-test-13`; the spool file `d00013-001` is a 15418-byte
PDF 1.4 page of the Writer document.

The print path is covered by `examples/cups-probe` and the WPS workflow runner.
